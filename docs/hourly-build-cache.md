# 2026-09-25 사이트 갱신 복구

9월 25일 02:05 KST부터 사이트 빌드가 소스별 6MB 전송 보호 상한을 넘어서 중단됐다.
첫 실패 계획은 본문 6,025,266 + 해시 목록 44,994바이트, 13:05 실행은
본문 10,024,214 + 해시 목록 49,758바이트였다. 원문 다운로드 전 검사에서 중단했으며
Supabase 청구 한도 초과 오류가 아니다. 수집은 계속됐고 마지막 정상 빌드는 01:09 KST였다.

PR #15는 체결 캐시를 UTC 날짜에서 UTC 시간 묶음으로 바꾼다. 완료된 시간은 내용이 같으면
재사용하고, 수정·삭제·늦은 커밋이 있으면 해당 시간만 다시 가져온다. 이전 날짜 캐시는
R2에서 해시를 검증하고 시간별로 나누므로 전환 때문에 운영 DB 전체를 추출하지 않는다.
이미 배포가 중단된 동안 쌓인 다른 테이블의 변경분도 처리해야 하므로 구형 체결 캐시를
전환하는 실행에만 기존 최초 구축 상한인 소스별 20MB를 적용한다. 전환 성공 후에는
6MB로 복귀한다. 복원·통합·사이트 생성이 성공해야 새 캐시를 발행한다.

테이블별 변경 본문 바이트와 묶음 수를 `[build-replica-plan]`에 기록한다.
본문·해시 목록 바이트는 Supabase 청구 전송량과 다르다.

검증: 일반 회귀 검사, PostgreSQL의 날짜→시간 전환 시 DB 원문 조회 0회,
같은 날 다음 시간 체결 추가 시 한 묶음만 조회, 변경·삭제·늦은 커밋·큰 정수·복원·경합 검사를
통과했다. R2 실제 자료의 전체 사이트 대조도 통과했다.
