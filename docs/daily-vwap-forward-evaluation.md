# 개별 아이템 평균 거래가 사전 발행 평가

버전 `daily-vwap-20261006-v1`. 기존 품목군 `research_forecast_batches`와 별도 실험이다. 가격선은 표시하지 않는다.

## 고정 규칙

- 정상 사이트 배포 완료 뒤 독립 Actions가 공개 summary/series JSON만 읽는다. 운영 DB·Neople API 조회 없음. 매일 KST 02시 이후 첫 정상 실행에 내일·3일·7일 뒤 하루 VWAP을 발행한다. 매일 03:40 KST schedule은 보조이며 지연될 수 있다. 빠진 과거 발행은 소급 생성하지 않는다.
- 전날까지 연속 일봉 21개·일평균 거래 5건 이상. 카드 호가 제외. 마지막 가격, 7일 평균, 같은 요일, 기존 추세+요일, 지수평활 2개, 고정 ARIMA 2개, KPSS/AICc 선택 ARIMA를 동시에 기록한다. 기준일 당일 자료는 제외되어 마지막 완료 일봉에서 2·4·8일 거리다.
- 선택 ARIMA 규칙은 `docs/arima-diagnostics-protocol-2026-10-06.md`와 동일. 모델 코드와 의존성 파일 해시를 버전에 고정한다. 변경 시 VERSION을 올려 별도 실험을 시작해야 한다.
- 공개 입력은 `daily-median-10x-v1`·`Asia/Seoul`로 고정한다. 버전·시간대가 없거나 다르면 발행·실측 확정을 중단한다. 같은 R2 실험 경로의 `input-protocol.json`을 최초 한 번만 저장해 검사하고, 새 발행·실측에도 정제 규칙을 기록한다. 기존 v1 모델 해시와 이미 저장된 원장은 변경하지 않는다. 2026-10-20 추가한 검사 이전 기록에는 이 메타데이터가 없으며 소급해서 추가하지 않는다.
- 목표일 종료 뒤 24시간 더 기다린 첫 정상 실행에 실제값을 확정한다. 예: 10월 7일 목표는 10월 9일부터 확정한다. 거래 5건 미만·공개 일봉 누락은 이유와 함께 평가에서 제외한다. 사후 백필로 고정 실제값을 바꾸지 않는다.
- R2 `research-v1/daily-vwap/<version>/protocol.json`, `issues/YYYY-MM-DD.json`, `actuals/YYYY-MM-DD.json`에 `If-None-Match: *`로 최초 한 번만 쓴다. 앱 수준 덮어쓰기 방지이며 관리자 삭제·수정까지 막는 Object Lock은 아니다. 발행에 전체 학습 입력·입력 해시·모델 진단·실제 발행 시각을 포함한다.
- MAPE, 품목 동일 비중 MAPE, 품목별 건수·오차·기준선, 목표 날짜 수, 대기·제외 건수를 계산한다. 서로 겹친 날짜의 평가를 독립 표본으로 취급하지 않는다. 좋은 모델을 사후 골라 서비스 성능이라고 주장하지 않는다.

## 결과와 실패 확인

GitHub Actions의 **개별 평균 거래가 예측 검증** 실행 요약에 전체 평가가 표시된다. `daily-vwap-evaluation` artifact의 `evaluation.json`에 품목별 결과, `report.md`에 요약이 있다. artifact는 30일 보관, 정본 R2는 삭제하지 않는다. 실패는 별도 워크플로 실패로 표시되며 수집·사이트 배포를 막지 않는다. 알림 수신은 계정의 Actions 알림 설정에 따른다. 다음 배포 완료 시 재시도한다.

2026-10-21부터 같은 코드 커밋·KST 날짜에서 02시 이후 당일 발행과 도래한 실측 확정 및 보고서 업로드가 모두 성공하면 완료 표시만 Actions 캐시에 저장한다. 다음 호출은 캐시가 있으면 npm/Python 설치·원장 전체 조회·평가 재생성 전에 종료한다. 캐시 누락·장애, 새 날짜, 새 코드에서는 기존 처리를 실행하며, 수동 실행은 캐시를 우회한다. 발행·실측·업로드 실패 때는 완료 캐시를 남기지 않아 재시도한다. 캐시는 성능 개선용이며 중복 발행 방지의 정본은 기존 R2 원장이다. 코드 테스트는 PR에서 실행한다.

사이트의 전체 Node·SQL·상세 예측 코드 테스트도 PR에서 실행한다. 배포에서는 동일 커밋의 검사 완료 캐시가 있을 때만 이 코드 테스트를 생략한다. 새 커밋·캐시 누락이면 정기 배포에서도 전체 검사를 다시 통과해야 한다. 운영 자료의 시간봉 정합성·집계 지연 검사, 예측 계산과 패키지 연구 입력 검증은 매 배포마다 유지한다.

공개 시계열은 유한한 기간만 담으므로 장기간 중단 후 실측 날짜가 사라졌으면 결측으로 고정된다. 수집량 자체도 API 상한을 가진다. 새 계정 자격증명이나 DB 테이블을 만들지 않는다.

기존 10월 6일 로컬 연구에서 저장한 예측은 소급 발행으로 가져오지 않는다. 새 자동화가 실제 실행된 시점의 발행부터 별도 전향 평가한다.
