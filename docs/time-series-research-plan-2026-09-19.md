**3. 최신 연구에서 가져올 것과 보류할 것**

**3-1. Chronos-2: 첫 번째 사전학습 모델 후보**

Chronos-2는 2025년 10월 공개된 시계열 사전학습 모델이다. 가격 한 줄뿐 아니라 관련 시계열, 과거에만 관측되는 변수, 미리 알려진 미래 변수를 함께 사용할 수 있다. 논문은 그룹 안에서 정보를 공유하는 attention과 결측 마스크를 설명한다. 따라서 가격·과거 매물·예정 이벤트를 비교하는 이번 질문에 기능적으로 맞는다. [논문](https://arxiv.org/abs/2510.15821), [모델 구조와 결측 처리](https://arxiv.org/html/2510.15821v1).

공식 120M 모델과 28M small 후보가 있으며, 확인한 두 모델 카드의 라이선스는 Apache-2.0이다. CPU 추론도 지원한다. 다만 개발팀 GPU 벤치마크를 우리 PC나 GitHub Actions 실행 시간으로 환산하지 않는다. 먼저 같은 입력으로 메모리·실행 시간·실패율을 측정하고 체크포인트와 라이브러리 버전을 고정한다. [120M 모델 카드](https://huggingface.co/amazon/chronos-2), [small 모델 카드](https://huggingface.co/autogluon/chronos-2-small).

적용 제안: 소형 모델의 실행 가능성을 먼저 확인한 뒤 가격만 입력한 경우와 외부 변수를 추가한 경우를 비교한다. 가중치를 새로 학습하는 fine-tuning은 첫 실험에서 하지 않는다. 결측을 입력할 수 있다는 사실이 관측되지 않은 실제 가격을 안다는 뜻은 아니다.

**3-2. 외부 변수를 지원한다는 것과 잘 활용한다는 것은 다르다**

ICLR 2026 TSALM 워크숍 연구는 단순한 목표값–외부 변수 관계를 통제 실험했다. 이 조건에서는 TabPFN-TS가 Chronos-2보다 관계를 잘 포착하는 경우가 있었으며, 아주 짧은 입력에서는 두 모델 모두 어려움을 보였다. 미래 목표값 자체를 외부 변수로 준 진단 실험도 포함되어 있으므로, 그 성적을 실제 시장 예측 성적으로 읽으면 안 된다. [저자 공개 논문](https://helios2.mi.parisdescartes.fr/~themisp/publications/tsalm26-covariateforecasting.pdf).

적용 제안: “좋아 보이는 변수 전부 추가”를 피한다. 동일한 모델에 가격만, 가격+매물, 가격+매물+달력을 순서대로 넣어 각각의 추가 효과를 측정한다. 매물 정보가 도움이 안 되면 그 결과도 그대로 남긴다.

**3-3. TabPFN-TS: 두 번째 후보, 첫 범위에서는 보류**

TabPFN-TS는 시계열을 시간 특성이 있는 표 형태의 회귀 문제로 다룬다. 현재 연구 방향에서 날짜·이벤트·아이템 특성이 중요하므로 비교할 가치가 있다. 다만 2025~2026 논문의 TabPFN-v2 기반 결과와 현재 저장소의 기본 모델은 같지 않다. 공식 도구는 기본적으로 클라우드 클라이언트를 사용하고 로컬 체크포인트에는 별도 라이선스 수락 절차가 있으므로, 모델·실행 방식부터 명시해야 한다. [논문](https://arxiv.org/abs/2501.02945), [현재 공식 도구](https://github.com/PriorLabs/tabpfn-time-series).

적용 제안: Ridge와 Chronos-2로 기준을 만든 다음, 추가 모델이 필요한 근거가 생기면 같은 시험에 넣는다. 기본 설정으로 외부 API에 데이터를 보내는 실행은 피하고 로컬 사용 조건을 먼저 확인한다.

**3-4. TimesFM-3: 기술 동향 참고, 현재 운영 후보에서는 제외**

Google이 2026-08-31 공개한 TimesFM-3도 여러 목표와 과거·미래 외부 변수를 함께 다룬다. 시계열 모델이 가격 한 줄의 연장에서 시장 맥락을 함께 다루는 방향으로 발전한다는 사례다. [공식 발표](https://www.research.google/blog/timesfm-3-a-zero-shot-foundation-model-for-multivariate-forecasting/).

현재 공식 저장소는 3.0 가중치를 비상업·비운영 용도로 제한한다. 무료 개인 사이트라는 이유만으로 운영 사용 조건을 충족한다고 가정할 수 없다. 이번 운영 실험 후보에서는 제외하고, 라이선스 범위 안의 로컬 연구가 필요할 때 다시 검토한다. 2.5 이하와 3.0의 조건도 구분해야 한다. [공식 라이선스 안내](https://github.com/google-research/timesfm#license-notice-for-pretrained-weights).

**3-5. 품목군 공동 학습: 지수 평균과 별개의 접근**

Global forecasting은 여러 시계열에 하나의 모델을 학습시키는 방식이다. 과거 연구에서도 단순한 공동 선형 모델이 경쟁력 있는 결과를 보였다. 최신 모델만의 아이디어는 아니며, 작은 설명 가능한 모델부터 시작할 근거가 된다. [Montero-Manso·Hyndman, 2020/2021](https://arxiv.org/abs/2008.00444).

적용 제안: 카드별 가격 수준은 정규화하고 아이템·업그레이드 단계·역할을 구분한다. 각 카드에서 관측된 학습 행을 이용하되, 같은 날짜의 모든 카드를 함께 학습/평가 쪽으로 이동한다. 버퍼와 딜러를 섞는 것, 0업과 맥스업을 섞는 것은 성능 비교로 결정한다. 카드 30종×10일은 서로 독립적인 300일이 아니다.

그룹 지수의 값은 별도 정의를 유지한다. 특정 구성원이 없다고 남은 구성원의 비중을 즉석에서 키우지 않는다. 관측률이 높은 핵심 구성을 새로 만들면 선정 기준일 이전 정보만 쓰고 새 지수 버전을 부여한다.

**3-6. 관측 상태 연구: 무매물·수집 실패를 가격 0으로 바꾸지 않기**

FreshRetailNet-50K(2025)는 시간별 품절 상태를 기록한 수요 데이터와 복원·예측 연구다. 판매가 관측되지 않는 이유를 기록해야 한다는 점이 이번 프로젝트와 연결된다. 다만 소매점 품절 수요와 경매장 API의 표본 누락은 관측 과정이 다르므로, 논문의 수요 복원식과 개선율을 던파 가격에 직접 적용할 근거는 없다. [논문과 데이터 설명](https://arxiv.org/abs/2505.16319).

적용 제안: 관측 상태를 다음 세 축으로 나눈다. 점검과 API 오류는 동시에 발생할 수 있어서 하나의 배타적 상태값에 억지로 넣지 않는다.

| 축 | 저장할 내용 |
|---|---|
| 수집 결과 | 정상 응답 / 요청 실패 / 실행 기록 없음 / 과거 원인 확인 불가 |
| 관측 시장 상태 | 매물 있음 / 정상 응답에서 해당 단계 매물 없음 / 판단 불가 |
| 달력 정보 | 공지된 점검 구간, 공지 시각, 적용 시각, 출처 |

400건 제한에 걸렸는지도 별도 표시한다. 정상 응답의 ‘매물 없음’은 API가 돌려준 범위에서의 판정이며, 다른 업그레이드 매물이 섞이고 응답이 상한에 닿으면 특히 주의해야 한다.

**3-7. 예측 범위: 실제 오차에 맞춰 보정하는 연구**

Adaptive conformal은 새로 관측되는 오차에 따라 범위를 조절한다. JMLR 2024 연구는 분포 변화에 대응하는 온라인 보정을 다루며, NeurIPS 2025 CPTC는 상태 변화와 예측 범위 보정을 결합한다. [Gibbs·Candès](https://www.jmlr.org/papers/v25/22-1218.html), [CPTC](https://proceedings.neurips.cc/paper_files/paper/2025/hash/12271b64c483ad8f6192eb6aaa102044-Abstract-Conference.html).

적용 제안: 사전 발행 오차가 쌓인 뒤 구간을 보정한다. 전체 포함률, 평상시/점검 전후 포함률, 평균 폭, interval score를 함께 본다. 넓히기만 해도 포함률이 올라가므로 포함률 하나로 채택하지 않는다. 이론적 보장도 가정과 보장 방식이 다르며, 매일 개별 예측이 반드시 80% 확률로 맞는다고 표현하지 않는다.

**3-8. 패키지 이벤트: 가격 예측과 인과 추론을 구분**

Old School RuneScape의 세금·아이템 소각 정책을 분석한 연구는 게임 업데이트가 경제적 개입 연구의 소재가 될 수 있음을 보여준다. 2022년 연구로 최신 모델 논문은 아니지만 도메인 관련성이 높다. 던파에서는 판매 종료·종결 교체·보상 공급 변경을 이런 관점으로 기록할 수 있다. [게임 경제 연구](https://arxiv.org/abs/2210.07970).

단순 전후 차이는 이벤트의 순수 효과가 아니다. CausalImpact 같은 방법도 이벤트의 영향을 받지 않는 비교 시계열과 전후 관계의 안정성을 가정한다. 같은 패키지 구성품이나 대체재는 오히려 직접 영향을 받을 수 있으므로 자동으로 대조군이 되지 않는다. [공식 방법과 가정](https://github.com/google/CausalImpact).

**3-9. 문장형 LLM의 역할**

NeurIPS 2024의 일부 LLM 기반 예측법 분해 실험에서는 LLM 부분을 빼거나 단순한 층으로 바꿔도 성능이 유지·개선됐다. 모든 LLM이나 시계열 사전학습 모델이 무용하다는 결과는 아니지만, 문장형 LLM을 넣는 것 자체를 연구 성과로 삼기 어렵다는 근거다. [연구 논문](https://arxiv.org/abs/2406.16964).

적용 제안: 공지에서 날짜·영향 품목·공급 변화 후보를 추출하는 보조 역할을 우선 고려한다. 출처와 추출 근거를 보관하고 사람이 확인한다. LLM이 생성한 예상 가격이나 사후 설명을 학습 정답으로 사용하지 않는다.

**4. 예측 목표를 먼저 고정**

1차 목표는 다음 날의 레전더리 0업 P10 일평균이다. 비교를 위해 전체 최저호가 일평균을 보조 목표로 남긴다. 두 지표 중 점수가 잘 나오는 것을 사후에 주목표로 바꾸지 않는다.

현재 P10은 ‘매물이 관측된 카드 종류마다 최저호가 하나를 뽑은 뒤, 그 가격 목록의 하위 10% 지점’이다. 모든 매물의 하위 10% 가격이나 10장을 살 때의 평균 구매비용이 아니다. 이를 시간별로 계산하고 유효 시간의 산술평균을 일별 목표로 사용한다. 종류별 최저가를 뽑는 방식과 분위수 인덱스 규칙까지 버전으로 고정한다.

P10은 최저가 하나보다 단일 저가 매물에 덜 좌우될 것으로 기대되지만, 이것은 안정성과 예측 성적으로 확인할 가설이다. 매물이 있는 카드 종류가 달라지면 P10도 구성 변화에 영향을 받는다. 정상 조회 수·매물 관측 종류 수·종목 ID별 상태가 필요한 이유다.

사용자의 실제 질문인 ‘재료 카드 10장을 사려면 얼마인가’는 후속 지표로 더 직접적이다. 이미 받아오는 0업 매물을 가격순으로 합쳐 관측 가능한 최저 10장의 총비용을 계산할 수 있다. 이 단계에서는 추가 API 호출보다 기존 응답 재사용을 우선한다. 카드의 재료 사용 자격·수량 의미를 검증하고, 수량 부족이나 불완전 조회에서는 확정 구매비용처럼 표시하지 않는다. 호가 관측값은 체결 보장이 아니다.

P10이라는 시장 횡단면 분위수와, 예측 분포의 q10·q90은 서로 다른 의미다. 화면과 데이터 필드에서 구별한다.

발행 시점은 KST 02시 이후 첫 정상 실행, 입력은 전날까지의 완료 관측, 목표는 발행일 다음 날 전체 일평균으로 고정하는 안을 권한다. 예를 들어 9/20 발행·9/19까지 입력·9/21 가격 예측이다. 기존 규칙과 비교하려면 마지막 관측일에서 2일 떨어진 값이라는 점을 명시해야 한다. 일반 모델의 ‘학습 끝 바로 다음 한 스텝’을 그대로 연결하면 목표 날짜가 어긋난다.

**5. 비교 실험 편성**

모델 수보다 무엇이 개선을 만들었는지 분리하는 데 초점을 둔다.

| 순서 | 비교 대상 | 입력/방식 | 답할 질문 |
|---|---|---|---|
| B0 | 마지막 가격 유지 | 마지막 유효 완료 일의 값 | 기본 가격 예측을 넘는가? |
| B1 | 전주 같은 요일 | 목표 요일의 직전 주 값 | 주간 반복만으로 충분한가? |
| B2 | 최근 7개 달력일 관측값의 중앙값 | 관측 수를 함께 기록, 자격 기준 사전 고정 | 단순한 완화만으로 급등락을 줄일 수 있는가? |
| R0 | 정규화된 Ridge 회귀 | 과거 가격과 달력 요일, 소수 특성 | 설명 가능한 작은 모델은 어떤가? |
| R1 | 같은 Ridge + 매물 | R0 + 과거 관측 매물 건수·관측 범위 | 매물 정보의 추가 가치가 있는가? |
| R2 | 같은 Ridge + 예정 이벤트 | R1 + 발행 당시 알려진 점검·이벤트 | 공지 정보의 추가 가치가 있는가? |
| C0 | Chronos-2 | 가격만 | 사전학습 자체의 이점이 있는가? |
| C1 | 같은 Chronos-2 + 매물 | C0 + 과거 매물·관측 범위 | 같은 정보가 다른 모델에서도 유용한가? |
| C2 | 같은 Chronos-2 + 예정 이벤트 | C1 + 알려진 달력 | 이벤트 입력의 이점이 있는가? |

처음에는 B0·B1·B2·R0·C0까지 완성한다. 매물·이벤트 특성의 기록 품질을 확인한 뒤 R1/C1, R2/C2를 추가한다. 각 비교는 같은 모델 버전·같은 목표 날짜를 사용한다. 관측 상태를 관리하는 품질 필터는 모든 비교군에 공통 적용한다.

후보 입력은 우선 과거 가격 변화, 과거 매물 건수, 정상 응답 비율, 매물이 있는 종류 수, 목표 요일, 공지된 점검 시간으로 제한한다. 고정 165종에서는 ‘종류 수’와 그 비율을 동시에 넣지 않는다. 비슷한 변수 수십 개를 작은 표본에 넣지 않는다.

미래 실제 매물량·미래 실제 체결량·사후 확정된 점검 종료 시각을 미리 아는 변수로 넣으면 안 된다. 당시 예정 시각과 나중에 확인한 실제 시각을 구분한다. 일별 데이터 표준화·변수 선택·모델 강도 선택도 학습 기간 안에서만 수행한다.

Chronos-2에 가격과 카드별 시계열을 함께 넣는 실험은 품목별 기록을 확보한 다음 단계로 둔다. 현재 전체 P10 이력만으로 165종 공동 학습을 했다고 말하지 않는다.

**6. 검증 설계와 화면 공개 기준**

시간순으로 학습을 끝내고 이후를 맞히는 rolling-origin 평가를 사용한다. 랜덤 행 분할은 사용하지 않는다. 벤치마크 순위 대신 우리 시장·목표·실제 발행 시간에서 얻은 결과로 결정한다. [시간순 평가 원칙](https://otexts.com/fpp3/tscv.html), [GIFT-Eval의 평가 범위](https://github.com/SalesforceAIResearch/gift-eval).

- 과거 재구성: 입력을 과거 날짜로 잘라 탐색한다. 당시 데이터 보유 상태까지 재현하지 못하면 그렇게 표시한다.
- 사전 발행: 모델·특성·목표를 고정하고 앞으로의 예측을 실제 가격보다 먼저 보관한다. 향후 채택 판단의 주 근거다.
- 버전 분리: 기존 2026-09-16-v1의 예측·실측을 수정하지 않는다. 데이터 정의와 모델 중 하나라도 바뀌면 새 버전을 부여한다.
- 날짜 일치: 같은 목표일에서 모든 비교군이 낸 예측을 비교한다. 별도로 전체 발행 성공률과 평가 제외 사유를 공개해 쉬운 날짜만 남는 문제를 확인한다.
- 결측 보존: 없는 실제값을 예측이나 보간값으로 채워 채점하지 않는다. 실패한 날짜도 원장에 남긴다.
- 발행 기록: 발행 시각, 입력 기준 시각, 학습 마지막 날짜, 목표 날짜, 모델/특성/집계 버전, 입력 해시, 결과, 실행 시간, 보류 사유를 보관한다.
- 점수: 주지표는 골드 단위 MAE와 같은 날짜의 B0 대비 개선율. MAPE는 기존 화면과 연결하는 보조 지표로 둔다. 다품목에는 종목별 점수와 동일 비중 요약을 함께 쓴다. MAE와 MAPE는 평가 대상이 다를 수 있으므로 미리 주지표를 정한다. [정확도 지표](https://otexts.com/fpp3/accuracy.html).
- 그룹 비교: 평상시, 목요일, 공지 점검 전후, 주요 이벤트 구간을 나눠 오차와 표본 수를 표시한다. 이벤트가 1건이면 일반적인 이벤트 성능으로 해석하지 않는다.
- 불확실성: 주 단위 의존을 고려하는 블록 재표집 등을 검토하되, 독립적인 주가 적을 때는 유의성 주장을 보류한다. 7일 예측의 겹치는 평가도 독립 표본으로 세지 않는다.

첫 운영 검토는 사전 발행 목표일 최소 28개와 그 안의 요일별 평가 가능 여부를 확인한 뒤로 제안한다. 28은 검토를 시작할 프로젝트 운영 기준이지 통계적 충분성 보장이 아니다. 전체 MAE가 B0보다 작고, 다른 단순 기준과 비교해 이점이 있으며, 특정 하루가 개선을 전부 만들지 않는지 확인한다. 개선의 불확실성이 크거나 이벤트 구간에서 불안정하면 실험 표시를 유지한다.

모델 선정을 위해 본 28일은 이후 성능의 독립 검증 구간이 아니다. 후보를 고른 뒤 별도의 미래 구간에서도 유지되는지 확인한다. 수치 기준을 결과에 맞춰 바꾸는 일은 새 실험으로 기록한다.

예측 범위는 80% 포함률·구간 폭·interval score를 함께 통과하는지 추가로 본다. ‘평균적으로 덜 틀림’, ‘방향을 맞힘’, ‘싸게 살 수 있음’은 별도 주장이다. 주간 최저 요일 예측이나 구매 유용성은 독립 목표로 설계하기 전에는 표현하지 않는다.

**7. Weekly 트렌드와 이벤트 연구 편성**

주간 연구 질문은 ‘목요일은 싼가’ 하나로 고정하지 않는다. 요일별 가격 수준, 전날 대비 변화, 점검 종료 후 몇 시간 동안의 움직임을 구분한다. 시간별 관측 240개가 있어도 같은 주의 자료라면 10주를 관측한 것과 같지 않다.

목요일과 정기점검이 늘 겹치면 두 효과를 분리하기 어렵다. 한 주 전체 평균으로 정규화한 그림은 사후 설명에 사용할 수 있지만, 그 주의 미래 가격이 들어가는 주평균을 예측 입력으로 사용하면 안 된다.

현재 18시간 기준은 운영상 선택이다. 긴 점검 때문에 목요일이 자주 탈락하면 남은 목요일만 보는 선택 편향이 생길 수 있다. 모든 시간 슬롯과 결측 이유를 보존하고, ‘관측 가능한 거래 시간의 평균’과 ‘동일 시간대를 비교한 평균’의 민감도 분석을 별도 버전으로 설계한다. 그래프를 보이게 하려고 목요일 기준만 느슨하게 바꾸지 않는다.

주간 효과의 더 안정적인 검토는 8~12개의 서로 다른 주를 첫 검토 구간으로 제안한다. 이것도 보편적인 최소 표본 공식은 아니다. 실제 관측 변동성과 효과 크기로 판단해야 하며, 급격한 종결 교체 전후는 같은 시장 상태라고 가정하지 않는다.

패키지 연구는 저장된 일정상 2026-11-05 판매 종료를 우선 대상으로 준비한다. 일정 변경이 가능한 만큼 공식 원문의 최신 날짜와 공지 이력을 구현 시 다시 확인한다. 8월 출시 전 자료는 부족하므로 출시 효과를 사후에 만들어내지 않는다.

| 항목 | 사전에 정할 내용 |
|---|---|
| 관측 대상 | 패키지·구성품별 VWAP, 관측 매물, 수수료 반영 구성 가치 차이 |
| 시간 축 | 처음 알려진 종료 공지, 예정 종료, 실제 종료 확인, 관련 업데이트 |

| 예고 반응 | 종료 직전부터 움직였는지 관찰. 종료 당일만 충격일로 단정하지 않기 |

한 번의 패키지 종료만으로 일반적인 ‘출시 D+별 가격 예측기’를 학습하기는 어렵다. 다음 패키지들도 같은 정의로 수집해 여러 주기를 쌓는다.

**8. 저장 용량과 실행 방식**

읽기 전용 DB 점검값은 전체 294 MB, listing_snapshots 41 MB, collection_runs 25 MB, legendary_card_floor 104 kB, research_forecast_batches 80 kB였다. pg_size_pretty가 표시한 DB/테이블 총크기이며, Supabase 대시보드 과금 사용량과 단위를 정밀 대조한 값은 아니다. Free의 공개 DB 한도는 500 MB다. [Supabase 요금표](https://supabase.com/pricing).

추가 설계안은 다음과 같다.

1. 레전더리 시간별 전체 지수에 조회 시도·성공·실패·상한 도달 수·스캔 시작/끝을 함께 기록한다. 전부 실패한 실행도 가격 NULL인 실행 기록으로 남긴다.
2. 이미 받아온 카드별 결과를 소형 행으로 저장한다. 우선 30일 시간별 원본과 장기 일별 요약을 보존하는 안을 용량 측정한다. 일별 요약에는 유효 시간 수·무매물/실패 시간 수·평균/마지막 가격·관측 매물 통계가 필요하다.
3. 165종×24시간×365일은 약 144.5만 행, 165종×365일 일별 요약은 약 6만 행이다. 실제 바이트 수는 행 크기와 인덱스로 측정한다. 일별 요약만 남기면 과거 시간대별 재분석이 제한되므로 시간별 원본은 외부 보관을 함께 설계한다.
4. 삭제는 일별 집계 대조와 외부 파일 내보내기·복원 검증이 모두 성공한 구간에만 허용한다. 외부 보관 대상은 시세·품질 데이터로 제한하며 게시판 인증 정보나 비밀값을 포함하지 않는다.
5. 모델 가중치·Python 환경·대형 실험 입력은 Supabase에 저장하지 않는다. 일별 예측 결과와 소형 메타데이터만 DB/정적 JSON으로 전달한다.
6. CPU 배치 실험을 수집·사이트 배포와 분리한다. 모델 실패나 다운로드 지연이 원래 수집·Pages 배포를 멈추지 않도록 한다. 하루 한 번의 가격 예측이면 매시간 모델을 다시 실행할 이유가 없다.

현재 크기로 1년 저장 가능하다고 결론내리지는 않는다. 첫 주 증가량과 보존 정책 적용 후 크기로 다시 계산한다. 백업을 로컬 PC에만 두면 PC가 꺼진 동안 Actions가 읽지 못한다. 사이트에 필요한 집계는 DB나 빌드가 접근할 수 있는 저장소에 두어야 한다.

**9. 실제 작업 순서와 완료 기준**

아래 시간은 착수 후 예상 작업량이다. 데이터가 쌓이는 대기 시간과 모델 정확도 검증 시간은 별도다. 자동 실행이나 일정 알림을 등록한 것은 아니다.

| 순서 | 작업 묶음 | 예상 | 산출물과 완료 기준 |
|---|---|---|---|
| P0-1 | 카드 마지막 상태 집계 수정 | 반나절~1일 | 같은 시간 ‘가격→무매물’, ‘무매물→가격’, 전부 무매물 사례 검증. 기존 v1 불변과 수정 후 영향표 확인 |
| P0-2 | 레전더리 품질·개별 기록 보강 | 1~2일 | 부분 실패·전체 실패·정상 무매물 구분. 같은 시간 중복 실행·중도 종료·재시도 기록 일관성 검증 |
| P0-3 | 품질 요약·보존 계획 | 1일 | 7일 후 사라지는 오류 요약 보존, 일별 집계 대조, 실제 저장 증가량 측정 계획 |
| P1-1 | 재현 가능한 입력·평가 도구 | 1일 | 날짜/입력/버전/해시 고정, 미래 날짜 유입·목표일 하루 밀림·결측 채점 방지 검증 |
| P1-2 | B0/B1/B2/R0/C0 로컬 비교 | 1~2일 | 같은 날짜 오차표, 실행 시간·메모리, 관측 부족 보류. 소형 모델 실행 적합성 판단 |
| P1-3 | 매물·이벤트 추가 비교 | 1~2일 | R1/C1과 R2/C2의 추가 효과 분리. 당시 알려진 이벤트만 입력되는지 검증 |
| P2 | 별도 버전 사전 발행 | 구현 후 최소 4주 관찰 | 실제값보다 먼저 저장, 중복 발행 시 불변, 실패일 보존, 28개 목표일 첫 검토 |
| P3 | 카드 품목군 공동 학습 | 입력 품질 확보 후 | 카드별/역할별 성적, 구성 변경 효과와 예측 효과 구분, 그룹 단위 시간순 평가 |
| P3 | 패키지 종료 관측 준비 | 지금부터 준비 | 공식 일정·대상·대조군·창 길이 고정, 종료 전 기록 확보 |
| P4 | 불확실성 보정·노출 판단 | 사전 오차 축적 후 | 구간 포함률·폭·점수, 후보 선정 후 별도 미래 구간 검증 |

가장 먼저 착수할 범위는 P0-1과 P0-2다. 가격 기록을 더 잃기 전에 이 부분을 보완하고, P1의 단순 기준 비교를 만든다. 1차 예측 비교는 레전더리 P10 하나로 제한해 결과를 해석할 수 있게 한다.

당분간 보류할 항목은 대규모 fine-tuning, 여러 신경망의 대회식 탐색, 미확인 게임 경제 인과 그래프, 확정 매수 추천이다. 품목군 연구에서는 가격을 더하면 전체 가격이 되는 것도 아니므로, 수량 합계용 계층 예측을 그대로 적용하지 않는다. 고정 가중 지수는 선형 결합으로 관리할 수 있지만 P10은 합계로 재조정할 수 없다. [합계 구조에 대한 예측 조정](https://otexts.com/fpp3/reconciliation.html).

이 계획의 성과는 모델 이름이 아니라 ‘어떤 시장 정보가 예측을 개선했고, 어떤 경우에는 예측을 보류해야 했는지’를 재현 가능한 기록으로 보여주는 것이다.
